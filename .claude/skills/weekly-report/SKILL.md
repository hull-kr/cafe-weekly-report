# 주간 판매 보고 만들기

새 주 폴더(예: `1026-1101`)에 들어온 지점별 판매 엑셀을 하나로 합치고, 그 숫자로 6장짜리 회의용 PPT를 만든다.

**사용자는 중간 질문 없이 끝까지 만들어 주기를 원한다.** 월요일 아침 회의 직전에 한마디로 돌리는 작업이라, 도중에 멈춰 물으면 보고서가 제때 나오지 않는다. 이상한 데이터는 아래 판단 원칙대로 가장 그럴듯하게 처리하고, 처리한 내용을 모두 '사후 점검 사항'에 남긴다. 사용자는 그것을 보고 회의 뒤에 지점에 확인한다. 묻는 대신 기록하는 것이 이 스킬의 핵심이다.

## 준비물 (프로젝트 폴더 기준)

- Python 은 `.venv\Scripts\python` 을 쓴다. PATH 의 `python` 에는 필요한 패키지가 없다.
- Node 패키지는 프로젝트 폴더의 `node_modules` 에 있다. 명령은 프로젝트 폴더에서 실행한다.
- 아래에서 `S` 는 이 스킬의 `scripts` 폴더(`.claude\skills\weekly-report\scripts`)를 뜻한다.
- 지점·메뉴·기준 단가·별칭은 `references\config.json` 에 있다.

## 결과물

`보고서\<주>\` 에 만든다. 사용자가 다른 출력 폴더를 지정하면, 아래 명령의 `보고서\<주>\` 를 모두 그 폴더로 바꿔 읽는다. 지난주 통합본을 새로 만들 때는 그 폴더 아래 `지난주\` 에 만든다.

| 파일 | 내용 |
|---|---|
| `통합_판매_<주>.xlsx` | `통합_판매` 시트(매출은 수량×단가 수식) + `사후점검` 시트(판단 내역과 원본 대비 검산) |
| `점검사항.json` | 합치기 단계의 판단 기록. 장표가 읽는다 |
| `장표데이터.json` | 장표용 숫자 |
| `주간보고_<주>.pptx` | 6장. 표지, 한눈에 보기, 지점별, 메뉴별, 요일별, 사후 점검 사항 |

원본 주 폴더에는 아무것도 쓰지 않는다. 결과를 주 폴더에 두면 다음에 합칠 때 원본처럼 섞여 들어가기 때문이다.

## 순서

### 1. 이번 주 폴더 정하기

사용자가 폴더를 말하면 그것을 쓴다. 말하지 않으면 프로젝트 폴더에서 이름이 `MMDD-MMDD` 인 폴더 중 기간이 가장 최근인 것을 고른다. 이미 `보고서\<주>\주간보고_<주>.pptx` 가 있어도 다시 만들어 달라는 뜻으로 보고 새로 만든다.

폴더 안의 메모(.txt, .md)는 합치기 스크립트가 내용을 읽어 `사후점검` 시트와 PPT 마지막 장에 '폴더 메모'로 자동으로 남긴다. 확인 필요 항목으로는 세지 않는다. "수요일 행사", "임시 휴무" 같은 메모가 어떤 판단을 설명해 주면, 7단계 보고에서 그 판단과 이어서 적는다. 예: "판교 바닐라라떼 5,000원은 메모의 수요일 행사와 맞음".

### 2. 합치기

```
.venv\Scripts\python -X utf8 S\merge_week.py <주폴더> 보고서\<주>\통합_판매_<주>.xlsx
```

- 머리글 이름과 표 모양(세로형/가로형)을 스스로 알아낸다. 파일마다 어떻게 읽었는지 `정보:` 줄로 찍는다.
- **끝 코드 3 (읽지 못한 파일)**: 그 파일만 직접 열어 보고(`.venv\Scripts\python -X utf8 -m markitdown 파일`) 표준 CSV 로 바꾼다.
  - 열: `지점,날짜,메뉴,수량,단가,매출`. 날짜는 `YYYY-MM-DD`, 모르는 칸은 비운다.
  - 확장자까지 포함한 원본 파일 이름 뒤에 `.csv` 를 붙여 저장한다. 예: `보고서\<주>\_변환\성수점_1102.xlsx.csv`. 그다음 `--adapter-dir 보고서\<주>\_변환` 을 붙여 다시 실행한다. 사후점검에 "Claude 가 직접 변환"으로 남는다.
  - 이 변환은 원본을 읽은 그대로 옮기는 일이다. 값을 고치지 말고, 판단은 스크립트 규칙에 맡긴다.
- **'새 지점'이 찍혔는데 기존 지점이 분명할 때**: 예를 들어 `gangnam_weekly.xlsx` 는 강남이고, 기존 지점 중 하나가 빠져 있다. 이럴 때는 `config.json` 의 그 지점 `별칭` 에 이름 조각(`gangnam`)을 추가하고 다시 실행한다. 정말 새 지점이면 그대로 둔다.
- **스크립트 밖에서 내린 판단은 `--note` 로 남긴다.** 별칭 추가, CSV 로 옮기며 내린 해석 등이 해당한다. 형식은 `--note "지점|유형|원본 상태|처리|근거|원본 파일"` 이고, 여러 번 붙일 수 있다. 사후점검 시트와 PPT 마지막 장에 확인 필요 항목으로 들어간다. 보고에만 적으면 회의 자료에는 남지 않는다. 장표 표 칸이 좁으니 '원본 상태'와 '처리'는 한 줄 남짓으로 짧게 쓴다.
  예: `--note "강남|지점 이름 해석|영문 파일 이름 gangnam|강남으로 집계, 별칭 추가|기존 지점 중 강남만 파일 없음|gangnam_weekly_1102.xlsx"`
- 변환 CSV 에 단가·금액이 없으면 스크립트가 기준 단가로 매출을 계산하고, '추정 매출'로 확인 필요 항목에 올린다.
- **'모르는 메뉴'**: 신메뉴로 보고 그대로 집계한다. config 에는 추가하지 않는다. 사용자가 확인한 뒤 넣을 일이기 때문이다.

### 3. 엑셀 수식 계산 확인

```
.venv\Scripts\python tools\skill_run.py xlsx recalc.py 보고서\<주>\통합_판매_<주>.xlsx 60
```

`total_errors` 가 0 이어야 한다. `사후점검` 시트의 '설명 안 된 차이'가 0 이 아니면, 그 지점 줄의 원인을 찾아 사후 점검 근거에 적는다.

### 4. 지난주 자료 찾기

이번 주 시작일 바로 전 7일이 지난주다(예: 1026-1101 → 1019-1025). 아래 순서로 찾는다.

1. `보고서\<지난주>\통합_판매_<지난주>.xlsx`. 출력 폴더를 따로 받았으면 `<출력폴더>\지난주\` 도 찾는다.
2. 그 기간의 예전 통합본. 프로젝트 맨 위의 `통합_판매.xlsx` 는 날짜 열의 기간이 **지난주와 정확히 같을 때만** 쓴다. 이번 주와 같은 기간이면 이번 주 자료이므로 쓰지 않는다. 쓰면 같은 주끼리 '전주 대비'를 하게 된다. 기간 확인:
   `.venv\Scripts\python -X utf8 -c "import pandas as pd; d=pd.read_excel('통합_판매.xlsx', sheet_name='통합_판매'); d=d[d['메뉴'].notna()]; print(d['날짜'].min(), d['날짜'].max())"`
3. 지난주 원본 폴더가 있으면 2단계처럼 합쳐 `보고서\<지난주>\` 에 만든다. PPT 는 만들지 않는다.
4. 다 없으면 전주 대비 없이 만든다. 장표에 "지난주 자료가 없어 전주 대비는 생략"이 자동으로 들어간다.

지난주 자료는 이미 지난 판단이 반영된 것을 그대로 쓴다. 2·3번 경우는 최종 보고에 어떤 자료로 비교했는지 한 줄 적는다.

`deck_data.py` 가 비교 방식을 자동으로 맞춘다. 덧붙여 손볼 필요는 없다.
- 지점이 빠지거나 새로 생기면 두 주 모두 자료가 있는 지점끼리 총매출을 비교한다. 장표에 "같은 지점 기준"이라고 적힌다.
- 휴무 등으로 영업일 수가 다르면, 그 지점의 증감은 문장·표·검토 제안 모두 일평균 기준으로 쓴다. 표에는 † 가 붙고, 총매출 기준 증감은 각주에 적는다.

### 5. 장표 만들기

```
.venv\Scripts\python -X utf8 S\deck_data.py 보고서\<주>\통합_판매_<주>.xlsx 보고서\<주>\점검사항.json 보고서\<주>\장표데이터.json [--prev <지난주 통합.xlsx>]
node S\build_deck.js 보고서\<주>\장표데이터.json 보고서\<주>\주간보고_<주>.pptx
```

- 문장, 제목, 검토 제안은 숫자에서 자동으로 만든다. 디자인은 회사 색 진초록 계열이고, 사용자가 확정했다.
- 검토 제안은 "~검토" 정도의 표현으로 둔다. 해석을 단정하지 않는다.

### 6. 검수 - 반드시 실제 PowerPoint 그림으로 본다

```
.venv\Scripts\python tools\skill_run.py pptx office/validate.py 보고서\<주>\주간보고_<주>.pptx
.venv\Scripts\python -X utf8 S\ppt_render.py 보고서\<주>\주간보고_<주>.pptx 보고서\<주>\_검수
```

- 출력된 PNG 6장을 모두 열어 본다. 글자 넘침, 겹침, 단어 중간 줄바꿈, `₩` 로 보이는 경로를 찾는다.
- 고칠 것이 있으면 `build_deck.js` 의 해당 장을 고쳐 다시 만든다. 이 고침은 다음 주에도 쓰일 스킬 자체의 개선이다.
- **LibreOffice 그림만 보고 판단하지 않는다.** LibreOffice 는 차트에서 `943만` 을 `943 만` 으로 띄우고, 한글을 단어 단위로 줄바꿈해서 PowerPoint 의 글자 단위 줄바꿈 문제를 숨긴다. PowerPoint 가 없을 때(`ppt_render.py` 끝 코드 2, "PowerPoint 가 없어")에만 LibreOffice 로 대신 보고, 그 사실을 보고에 적는다.
- `ppt_render.py` 가 "PowerPoint 가 파일을 열지 못함"이라고 하면 그 파일은 회의에서 열리지 않는다. 반드시 원인을 고친다. 차트 XML 을 직접 손대면 이렇게 된다.
- 검수가 끝나면 `_검수` 폴더와 `_변환` 폴더는 지워도 된다. `_변환` 은 다시 만들 때를 위해 남겨도 된다.

### 7. 사용자에게 보고

짧게 쓴다.
- 만든 통합 엑셀과 PPT 의 경로 (json·검수 그림은 보조 파일이라 적지 않아도 된다)
- 이번 주 총매출과 전주 대비(있으면), 1위 지점과 1위 메뉴
- **사후 점검 사항**: 확인이 필요한 판단 목록. 지점, 무엇을 어떻게 처리했는지, 매출 영향
- 메모 파일 내용을 판단에 쓴 경우나 지난주 자료를 원본에서 다시 만든 경우에는 그 사실

## 판단 원칙

`merge_week.py` 가 아래 규칙을 이미 적용한다. 원칙을 알면 스크립트가 못 다루는 경우에도 같은 방향으로 판단할 수 있다. 공통 원칙은 **원본 숫자를 최대한 살리고, 실수가 분명할 때만 고치고, 고친 것은 모두 남기는 것**이다.

| 상황 | 처리 | 이유 |
|---|---|---|
| 같은 날·메뉴·수량·단가인 줄이 또 있음 | 한 줄만 남김 | 복사 실수. 사용자가 2026-10 대전 건에서 이렇게 결정함 |
| 수량이 음수 | 환불로 보고 그대로 차감, 비고 `환불` | 사용자 결정(2026-10) |
| 하루 기록이 통째로 없음 | 휴무로 추정, 일평균은 영업일 기준 | 사용자 확인(2026-10 대전 휴무) |
| 이번 주 기간 밖 날짜 | 제외 | 다른 주 자료가 섞인 것 |
| 합계·소계 줄 | 제외 | 통합 표에서 다시 구함 |
| 단가 칸만 틀리고 금액은 기준 단가와 맞음 | 기준 단가로 고침 | 단가 칸 입력 실수 |
| 금액이 기준과 다른 단가로 일관됨 | 파일 값 그대로 | 할인·행사·가격 변경일 수 있어 실제 판매가를 존중 |
| 단가는 기준과 같은데 금액이 안 맞음 | 수량×단가로 다시 계산 | 금액 칸 입력 실수 |
| 기준에 없는 메뉴 | 새 메뉴로 그대로 집계 | 신메뉴 가능성 |
| 지점 파일 없음 | 그 지점 빼고 보고 | 지점에 자료 요청 필요 |
| 일부 메뉴만 있는 날·유난히 낮은 날 | 그대로 집계하고 기록만 | 단축 영업일 수 있어 숫자를 만들어 넣지 않음 |

위 표에 없는 상황도 같은 원칙으로 처리한다. 스크립트 밖에서 판단했다면 2단계 명령에 `--note` 를 붙여 다시 돌린다. 그래야 엑셀과 PPT 양쪽에 같은 내용으로 남는다. JSON 이나 엑셀을 손으로 고치면 둘이 어긋나므로 그렇게 하지 않는다.

## 문제가 생기면

- `.xls` 파일: LibreOffice 로 `.xlsx` 변환본을 `_변환` 폴더에 만든다. 그 다음 `--adapter-dir` 대신 그 변환본을 읽게 하거나, CSV 로 바꿔 넣는다.
- 메뉴 이름이 기준 메뉴의 오타·변형이 분명함(예: `크로와상`): 별칭 추가는 config 를 바꾸는 일이다. 같은 메뉴가 분명하고 단가도 같을 때만 별칭에 추가하고, 보고에 적는다.
- 지점이 늘거나 줄어도 장표는 자동으로 맞춰진다. 6개를 넘으면 지점 표 줄 높이가 줄어든다.
